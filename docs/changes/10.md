# Progress board as a download: change spec v1

Status: draft v1 · Issue: #10 · Profile: prototype · Size: M · Builds on #8

## 1. Problem
To open the board today you need Node, `npm install` and a terminal, and a sign-in through the GitHub command-line tool. A newcomer has none of these.

## 2. Goal
Two ways in, and the user picks one: download one file for Mac or Windows and double-click it, or type one `npx` command. Either way they sign in with GitHub in the browser and pick their project from a list.

## 3. Scope in
- A one-file app per system, built with Node's single executable feature, with the page and sample data inside.
- A release workflow that builds it on GitHub's Mac and Windows machines, starts each one to prove it runs, and makes a draft release.
- An npm package with a `team-board` command (not published until the owner says so).
- "Sign in with GitHub" (GitHub's device sign-in for apps) and a project picker, saved in the user's own settings folder.

## 4. Scope out
Paid code signing (owner chose "Not yet, show the warning steps"), auto-update, Linux download, publishing to npm.

## 5. Acceptance criteria
- **AC1 One file runs.** The built app starts with `--demo` and serves the page and `/api/board` with no Node installed and no other files. Proved on Linux here and on macOS and Windows by the release workflow's smoke test.
- **AC2 npx runs.** The packed package installs with no runtime dependencies, and `npx team-board --demo` serves the board.
- **AC3 Sign in.** With no saved sign-in and no `GITHUB_TOKEN`, the page shows a code to copy, a button that opens GitHub, and checks every few seconds until GitHub says yes. A refused or expired code says so in one plain sentence. The token is saved only in the user's settings folder, readable only by them.
- **AC4 Pick a project.** After sign-in the page lists the projects the user gave the board access to, with a link to give access to more, and a box to type `owner/name`. The choice is saved; "Change project" brings the list back.
- **AC5 Sign out.** "Sign out" deletes the saved sign-in.
- **AC6 Only this page can act.** Every action request must come from the board's own page (Origin check, JSON body), and the demo refuses all of them except "Stop".
- **AC7 Honest warnings.** The README's download steps show the Mac "Open Anyway" and Windows "More info, Run anyway" clicks, and say plainly why the warning appears.
- **AC8** All of #8's acceptance criteria still hold.

## 6. Constraints (owner-stated only)
- No paid signing yet. No npm publish without the owner. Keep CI lean.
- Plain words a 10-year-old could follow.

## 7. Non-functional targets
- The release workflow runs only on a `v*` tag or by hand, with 15-minute timeouts.
- The app reads only Issues, Pull requests and Metadata (a read-only GitHub App).

## 8. Owner setup
Create the board's GitHub App once: read-only Issues, Pull requests, Metadata, Contents, plus Secrets and Variables read and write for the Settings page (#16); device flow on; no webhook; public. The client ID and the app's short name aren't secret and go in `server/auth.ts`. Until then sign-in works only with `GITHUB_TOKEN` or the GitHub command-line tool.

## 9. What is not tested
Nobody has yet double-clicked the downloaded file on a real Mac or Windows computer. The release smoke test runs the same file from a terminal on GitHub's machines, which skips the browser download and the system's first-open warning.
