# Team projects first, and a next step when there's none: change spec v1

Status: draft v1 · Issue: #29 · Profile: prototype · Size: S · Builds on #10

## 1. Problem
The picker lists every repository the sign-in can see. A newcomer with one team project gets a long list of unrelated ones (owner, 2026-11-13: "It should only show the projects that use the team"). Someone who opens the board before Ella has made their project sees "The board can't see any projects yet" and nothing to do next.

## 2. Acceptance criteria
- **AC1 Team projects.** `GET /api/projects` marks each project `team: true` when `TEAM.md` exists at its root, and lists those first. It looks inside at most 100 projects, 8 at a time. A look that fails counts as not a team project and never fails the list.
- **AC2 Only team projects up front.** The picker shows team projects. The rest, and the "type its name" box, sit behind "Show all your projects (N more)".
- **AC3 Straight to your project.** On the first run (no project saved yet), exactly one team project opens straight away, with no list. "Change project" always shows the list.
- **AC4 No project yet.** With no team project, the page says "No project yet", tells the person to talk to Ella first (three short steps, linking the "Your first project" lesson), and has a Check again button. The "Let the board see it on GitHub" link stays for a board signed in through its GitHub App.
- **AC5** #8, #10, #11 and #16 still hold.
