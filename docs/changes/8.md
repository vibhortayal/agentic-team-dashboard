# Progress board: change spec v1

Status: draft v2 (stack changed to TypeScript by the owner, 2026-11-12; see docs/decisions/0001-stack.md) · Issue: #8 · Profile: prototype · Size: M

## 1. Problem
A newcomer can't read GitHub labels and comments. Today they only learn where their project stands, or that the team is waiting on them, by asking Ella.

## 2. Goal
One page on the user's own computer that shows, in plain words, what is waiting on them and how each piece of work is going. It reads only what the team already writes on GitHub ([github-state](../../.team/docs/github-state.md)). It writes nothing and runs no AI.

## 3. Scope in
- A small local server that reads the project's open issues, open PRs and their team comments, and serves one page on `http://localhost:4321` (127.0.0.1 only).
- A demo mode with built-in sample data.

## 4. Scope out
Ella's chat, Approve buttons, the autonomy dial, starting agents, packaging an installer.

## 5. Acceptance criteria
- **AC1 You're needed.** Every open issue or PR labelled `needs-human` appears under "Waiting for you", with a plain sentence for its `human:` label and a link to the comment that asked (the latest team comment with `"to":"owner"` or a `human` field; else the item itself).
- **AC2 Ella's own calls.** The latest team comment from Ella with kind `note` on an open item shows greyed out under "Ella handled these herself", with her first line as the reason.
- **AC3 Progress.** Open tickets are grouped by their `stage:` label in everyday words (Getting ready, Ready to build, Being built, Being checked, Waiting for you, Done). Each card names who holds it by persona (from the `role:` label) and shows the header line of its latest team comment.
- **AC4 Never "done" without a check.** A ticket shows "Checked: passed" only when its latest verdict comment says PASS. Otherwise it shows "Not checked yet" (or "Checked: needs fixes" on BLOCK). A `stage:done` label without a PASS shows "Not checked yet".
- **AC5 Can't read status.** If GitHub can't be read (no sign-in, network, rate limit), the page says so in one plain sentence, links the repo on GitHub, and shows no stale data as current.
- **AC6 Secrets masked.** Every string the server sends to the page passes through one mask. Known key shapes become `[hidden: <kind>]`; a value after a name ending in KEY, TOKEN, SECRET or PASSWORD is hidden; if masking fails, the whole line is hidden. A planted file of fake keys, one per shape, all come out masked.
- **AC7 Demo.** `npm run demo` shows the board from sample data with no network and no sign-in.
- **AC8 Local only.** The server listens on 127.0.0.1, not on all addresses.
- **AC9 Plain words.** No label names, JSON or GitHub jargon on the page's first screen.

## 6. Constraints (owner-stated only)
- Runs on the user's own computer; no new bill; reads GitHub, never runs the model.
- Plain words a 10-year-old could follow; the target user knows Google and ChatGPT only.
- Keep CI lean.

## 7. Non-functional targets
- TypeScript: React page built with Vite, Node 22.18+ server with no framework; one `npm install`.
- One GitHub read per minute at most (cached); a project with 50 open items loads in under 5 seconds.

## 8. Data model
`/api/board` returns `{repo, updated, error, needed[], handled[], columns[{key,title,cards[]}]}`. Each card: `{number, title, url, kind, stage, holder, update, check, needed}`. All strings pass the mask.

## 10. Screens
One page: header (project name, last read time, refresh), "Waiting for you", "Ella handled these herself" (greyed), then the stage columns.

## 13. Risks
- Sign-in for the user's GitHub: this slice uses the GitHub CLI's sign-in or a `GITHUB_TOKEN` if present; a friendlier sign-in is a later ticket.
- A newcomer may not have Node installed; the coding assistant installs or explains it.

## 14. Open questions
None blocking.
