# The board as a Mac app that updates itself: change spec v1

Status: draft v1 · Issue: #33 · Profile: prototype · Size: M · Builds on #10, #28

## 1. Problem
Today the Mac download is a lone program that opens the board in a browser tab and leaves a Terminal window open. Each new version means downloading again by hand. The owner wants a small app of its own that keeps itself up to date (project thread, 2026-11-13 and 2026-11-14).

## 2. Goal
A normal Mac app, "Team Board", that shows the board in its own window and updates itself from this repo's published releases. Ella's chat is not part of it yet.

## 3. Scope in
- `desktop/`: an Electron app that starts the board's own server inside the app and shows it in a window. Its own `package.json`, so the npx package and the one-file app don't change.
- Self-update with electron-updater from this repo's GitHub Releases.
- `release.yml`: a Mac job that builds the app as a disk image and a zip, signs it with the Developer ID, has Apple check it, smoke-tests it, and adds it to the draft release with the update file.
- `server/main.ts` gains `startBoard()`, so the app starts the same server the one-file app does.

## 4. Scope out
Ella's chat, a Windows app, an Intel Mac build, an app icon, refreshing `.team/` in projects, dropping the lone Mac program (the README still points to it; a docs PR switches it once a signed app has shipped).

## 5. Acceptance criteria
- **AC1 One window.** Opening the app starts the board on this computer only (127.0.0.1) and shows it in a window titled "Team Board". No Terminal window, no browser tab. Closing the window quits the app and stops the board.
- **AC2 Same board.** Everything #8, #10, #11 and #16 show works the same in the window, including sign-in, the project picker and Settings. `--demo` shows the sample project.
- **AC3 Links leave the app.** A link to anything other than the board (GitHub, a try-it link, a help page) opens in the person's browser, never inside the app window.
- **AC4 Locked down.** The page gets no access to the computer: no Node in the page, context isolation and the sandbox on.
- **AC5 One copy.** Opening the app again brings the open window forward instead of starting a second board.
- **AC6 Updates.** A packaged app checks this repo's latest published release when it opens and every 6 hours. A newer version downloads in the background; then the app asks "A new version of Team Board is ready. Restart now?" with Restart and Later. Later installs it the next time the app quits. The app menu has "Check for Updates…", which also says when it's already up to date. No network or a failed check stays quiet (only the menu check says it couldn't check). Draft releases are never offered.
- **AC7 Release build.** The release workflow builds `Team-Board-<version>-arm64.dmg`, `Team-Board-<version>-arm64.zip`, its `.blockmap` and `latest-mac.yml` with the release's version, signs and notarizes them when the Developer ID secrets are set (ad hoc otherwise, with a warning that updates need the signed build), starts the built app with the sample project and checks it serves the board, and attaches the files to the draft release.
- **AC8** The one-file apps, the npx package and their tests are unchanged.

## 6. Constraints (owner-stated only)
- The person never opens a terminal or GitHub. Plain words.
- Buy, don't build: standard Electron tools, no own updater.

## 7. Permissions and secrets
No new ones. The Mac job reuses `MAC_CERT_P12`, `MAC_CERT_PASSWORD`, `APPLE_ID`, `APPLE_TEAM_ID` and `APPLE_APP_PASSWORD` (#28). Updates read the public releases with no sign-in.

## 8. New dependencies (in `desktop/package.json` only)
`electron` 45.2.3 and `electron-builder` 26.18.1 (build only), `electron-updater` 6.8.12 (inside the app). MIT, standard for signed self-updating Electron apps, each released at least 7 days ago. Needs `deps-approved`.

## 9. Not tested
A real update from one signed release to the next (needs two published, signed releases), and a person opening the downloaded disk image. Self-update only works when both versions carry the same Developer ID signature.
